# Neutron rules

Neutron is a desktop application framework built from Zed's crates. Read this section before changing
anything; the sections between the `upstream` markers below are synced from Zed's `.rules`.

## Where code goes

1. **Never edit `core/`, `assets/`, `apps/ide/` or the generated root files** (`Cargo.toml`,
   `Cargo.lock`, `.cargo/config.toml`, `rust-toolchain.toml`). `cargo neutron sync` overwrites them and
   `cargo neutron verify` fails on any difference from upstream. Fix behaviour in core by sending a PR
   to Zed; if it cannot wait, add a shim or take the file into `riso/` and record its origin in
   `upstream.toml`.
2. A reusable UI component that knows nothing about a product goes in `riso/` as a base plus traits
   (for example `StatusBar` + `trait StatusItem`). See `riso/AGENTS.md`.
3. A concrete component shared by the apps of one product goes in `crate/`, implementing the traits
   from `riso/`.
4. Entry points, wiring and business logic go in `apps/<app>/`.

## Dependency direction

`apps/<app>` → `crate/*` → `riso/*` → `core/*`. Nothing outside `apps/ide` may depend on a crate in
`apps/ide`; `cargo neutron verify` checks this.

## Workspace changes

- Add workspace members, dependencies or cargo aliases in `neutron.workspace.toml`, then run
  `cargo neutron sync`. Do not edit the root `Cargo.toml` by hand.
- Change where an upstream crate lives only through `upstream.toml`.
