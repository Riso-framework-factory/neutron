# Neutron

Neutron is a desktop application framework built from [Zed](https://github.com/zed-industries/zed)'s
crates: GPUI, the UI kit, themes, settings, keymaps, persistence and platform services. It follows Zed
upstream every day.

> Status: porting in progress. See [docs/adr](docs/adr) for the decisions behind the layout.

## Layout

| Path | Owner | Contents |
|---|---|---|
| `core/` | upstream, **read-only** | Zed crates copied verbatim and synced daily |
| `assets/` | upstream, read-only | Zed's `assets/` (fonts, icons, themes, keymaps, default settings) |
| `riso/` | Neutron | Shims for Zed's identity crates and reusable base components |
| `crate/` | you | Shared components of your product |
| `apps/` | you | App entry points; `apps/ide` is a mirror of Zed used as a canary |
| `tooling/` | upstream + Neutron | `xtask`, lints, and `neutron_cli` (`cargo neutron …`) |

Which crate goes where is data, not folder state: see [`upstream.toml`](upstream.toml).
The root `Cargo.toml`, `Cargo.lock` and `.cargo/config.toml` are generated by `cargo neutron sync`;
put Neutron-specific changes in [`neutron.workspace.toml`](neutron.workspace.toml).

## Syncing with upstream

```sh
git clone https://github.com/zed-industries/zed ../zed
# The first run builds the tool before the `cargo neutron` alias exists.
cargo run --manifest-path tooling/neutron_cli/Cargo.toml -- sync --upstream ../zed
cargo neutron verify --upstream ../zed
```

### Reviewing the daily sync pull request

`.github/workflows/upstream-sync.yml` opens or updates one pull request from the `sync/upstream`
branch every day. Its description is the sync report. It is never merged automatically:

1. Read the labels and the report. `sync-triage` means new upstream crates to classify in
   `upstream.toml`, crates moving in or out of core, or a `verify` finding; `sync-conflict` means a
   shim or riso file has conflict markers to resolve. "Riso files to port" lists upstream commits
   for watch-mode files in `riso/`; port what matters and run `cargo neutron ack <path>`.
2. Check out the branch and the upstream commit named in its `Upstream-Commit:` trailer, then run
   `cargo neutron doctor --upstream ../zed`. It runs `verify`, then `cargo check --all-targets`
   on core, shims and riso, then `cargo check -p zed` for the IDE canary.
3. Merge when `doctor` passes.

Run the mirrored IDE with an isolated data directory so it does not touch an installed Zed:

```sh
cargo run -p zed -- --user-data-dir /tmp/neutron-ide
```
